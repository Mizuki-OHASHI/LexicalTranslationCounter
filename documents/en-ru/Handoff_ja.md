# en-ru 引き継ぎ資料

ロシア語の実装を引き継ぐ方へ。

この文書を書いた人間は**ロシア語ができません**。パイプラインが端から端まで動く状態までを作り、
ロシア語の判断が必要な箇所を全部洗い出して残してあります。以降で「決めてください」と書いてある
ものは、コードが壊れているという意味ではなく、**妥当な選択肢が複数あって誰も判断していない**
という意味です。

ネイティブ判断が要る項目でも、根拠になる実行例・何が問題になりうるか・参照先をセットで
書いてあります。判断に迷ったら**保留してその旨をコメントに残す**のが正しい対応です。
勘で決めて先に進むより、未決のまま可視化されている方がずっと安全です。

## 1. 現状の品質（正直な数字）

200行の smoke データで **90 関係 / 180 件**。手作業で照合した結果は
**型レベル精度 約86%、トークンレベル 約89%**（77関係が正しい、9が誤り、4が判断保留）。

**この数字を良いと受け取らないでください。** 理由:

- wordlist が**同じ200文から自動生成**されているので、語彙は当たって当然
- 行レベル再現率は 51%（200行中102行しか関係を産まない）
- しかも **関係が出なかった98行のうち97行は、アライメント失敗ではなく wordlist の語彙不足**で落ちている
- モデルはファインチューニング無しの素の `bert-base-multilingual-cased`
- 誤りの約半分はロシア語の問題ではなく**コーパスのノイズ**

つまりこれは「配管が通っていることの確認」であって、品質測定ではありません。
**本物の wordlist ができるまで、品質を語れる状態にありません。**

言語的に最大の単一誤りは A1（`big → больший` が形容詞14件中5件）です。

## 2. Part A — ロシア語の判断が要る作業

主な武器は `src/normalizer/normalize_data/ru/*.csv` です。形式はヘッダ無しの `元の語,正規化後`。

**この表はロシア語だけ正しく動きます。** 他の言語は `pandas.read_csv(..., index_col=0).to_dict()`
で読んでいて、結果が `{1: {元の語: 正規化後}}` になるのに外側の dict を引いているため、
**一度も効いたことがありません**（en の約6000語の整備済み例外も全部素通り）。
ロシア語版だけ正しく読むように書いてあります。

さらにロシア語版は**表層形とレンマの両方で引きます**。屈折語で表層形キーだけだと全格変化を
列挙する羽目になるので、「レンマが間違っている」ケースは **1行**で直せます。

### A1. `большой` が `больший` になる問題を直す

**所要: 半日。最初にこれをやってください。** 効果が最大で、例外表の使い方も覚えられます。

```
большой -> большой   （正しい）
большая -> больший   （誤り）
большие -> больший   （誤り）
большим -> больший   （誤り）
```

主格男性単数だけ正しく、他は全部比較級 `больший` に化けます。実際の出力で
`big → больший` が5回出ており、**形容詞関係の中で最頻出**です。

原因は pymorphy2 が `большой` と `больший` に**同じスコア 0.500 を与えている**ことです。
Slovnet は正しく `Degree: Pos`（原級）と判定しているのですが、MorphVocab がそれを識別に
使えていません。**形態素素性を渡しても直りません**（確認済み）。ライブラリ側の限界です。

**あなたが決めること:** ロシア語の比較級（`больше`, `лучше`, `выше`, `сильнее`）を
辞書項目として独立させるか、原級に寄せるか。Media of Langue は「語の意味」を描くものなので、
`большой`（大きい）と `больший`（より大きい）を別ノードにするかは設計判断です。

**やり方:** `a_normalize.csv` に1行足すだけで全屈折形が直ります。

```csv
больший,большой
```

**完了の目安:** 再実行して `big → большой` になり、`больший` は本物の比較級の文
（例: 「Все большей популярностью」）でだけ出る状態。ついでに `wordlist_ru_adj.csv` の
他の語も同じ原級／比較級の取り違えが無いか確認してください。

**関連する未検証の問題:** 比較級を**副詞として**引くと形容詞のレンマが返ります。

```
лучше   (r) -> хороший   （хорошо であるべき）
быстрее (r) -> быстрый   （быстро であるべき）
выше    (r) -> высоко    （これは正しい）
```

一貫していません。`r_normalize.csv` で個別に潰すか、別の方法を考えるかの判断が要ります。

### A2. 品詞マッピングを決める — 代名詞・固有名詞・接続詞を辞書に入れるか

**所要: 1日。wordlist を作る前にやってください。** 何が辞書に入るかが決まります。

`src/ltc/constants.py` の `UD_POS_TO_LTC_CODE` は `PRON→n`、`PROPN→n`、`CCONJ→r`、`SCONJ→r`
と写しています。これは spaCy 系言語（de/es/fr/it）と**共有**されている表です。
英語やドイツ語では機能語が内容語バケツに流れ込まないので実害が出ていませんが、
ロシア語では出ています。

**代名詞が名詞になっています。** 現在の `wordlist_ru_noun.csv`（111語）に含まれるもの:

```
весь вы его их мы он она они ты что это
```

**接続詞が副詞になっています。** `wordlist_ru_adverb.csv` は **全16語がこれで全部**です:

```
более где домой еще или как когда можно назад но очень снова тогда тоже что чтобы
```

`или, но, что, чтобы` は接続詞、`можно` は述語副詞（категория состояния）。
副詞チャンネルは現状ほぼ使い物になりません。

**固有名詞が普通名詞と混ざります。** `Роман→роман`、`Вера→вера`、`Надежда→надежда`、
`Москва→москва`。ロシア語は人名によく使う語が抽象名詞と同形なので、他言語より影響が大きいです。

**副作用:** 内容語の品詞コードが付いたトークンは `group_aligned_words` で「独立語」扱いになり、
1語彙単位として貼り合わせる範囲が広がります。代名詞に品詞コードを与えると、この貼り合わせが
頻繁に発火します。

**やり方:** 共有の `UD_POS_TO_LTC_CODE` を直接いじらないでください（de/es/fr/it に波及します）。
`NatashaRussianBackend` のコンストラクタは既に `pos_map=` を受け取るので、
ロシア語専用のマッピングを渡してください。

**完了の目安:** どの UD タグをどの LTC コードに写すかをロシア語について明示したリストがあり、
`pos_map=` で実装され、`documents/en-ru/Readme.md` に理由が書かれ、smoke wordlist が再生成
されている状態。代名詞を残すなら、UD タグ `PRON` でレンマ化する必要があります
（`NOUN` で引くと格変化が潰れません。`PRON` なら `меня→я`、`нас→мы`、`его→он` と正しく動きます）。

### A3. ё / е の方針を決める

**所要: 半日。wordlist を作る前に。** 全キーの綴りが決まります。

MorphVocab は出力で ё を е に潰します。確認済み:

```
ёлка → елка      ребёнок → ребенок    чёрный → черный
ещё  → еще       Орёл    → орел       нёбо   → небо
```

結果として2つ問題が起きます。

1. **ё で綴った wordlist エントリは永久にマッチしません。** 外部辞書から wordlist を作る場合、
   同じ正規化を通さないと該当語のカウントが恒久的にゼロになります。
2. **別語彙が併合されます。** `нёбо`（口蓋）/ `небо`（空）、`Орёл`（都市名）/ `орел`（鷲）。

Media of Langue はこの文字列をそのままユーザーに見せるので、マッチングの問題であると同時に
**表示の問題**でもあります。

**完了の目安:** 方針が `documents/en-ru/Readme.md` に書かれていること。加えて、
ё を含む wordlist エントリを読み込み時に弾くか畳むかするガードがあること
（無いと、整備した辞書が黙ってゼロカウントになります）。高頻度の同形異義併合を
`n_normalize.csv` で分けるかは別途判断。

### A4. 動詞の体（вид）・再帰・形動詞の方針を決める

**所要: 1日。** 既存の言語に前例が無い領域です。

現状、以下は全て**別項目**になります。

- 体のペア: `делать` / `сделать`
- 再帰動詞: `открывать` / `открываться`
- 形動詞（причастие）: Slovnet は UD の規約どおり VERB として扱いますが、
  文脈によって ADJ になることもあります
- 副動詞（деепричастие）

英語の `do` は `делать` と `сделать` の両方に対応しますが、ロシア語話者から見て
これらが辞書上「同じ語」かどうかは自明ではありません。en/ja/de には対応する問題が無いので、
参考にできる前例がありません。

**参考:** UD の規約では、ロシア語の形動詞は `VerbForm` 素性を持つ **VERB** として注釈されます
（形容詞的に使われていても）。[UD Russian](https://universaldependencies.org/ru/) を参照。

**完了の目安:** 体・再帰・形動詞・副動詞それぞれについて「1項目にする / 分ける」の判断が
文書化され、`v_normalize.csv` に反映されている状態。判断がつかないものは
**「保留」と明記して残してください**。

### A5. コピュラ（繋辞）の扱いを決める

英語の `be` が実際の出力で3つのロシア語に割れています。

```
be → являться  x2   （正しい）
be → есть      x1   （「На одной из небольших террас есть джакузи」— アライメントは正しい）
be → подходить x1   （「is perfect for」/「идеально подходит」— 意訳）
```

ロシア語には現在形のコピュラがありません。`en_zh` は英語のコピュラを抑制するルールを
持っていますが（`TokenIgnoreRule(be_l, offset=0, require_next_pos="v")`）、
en_ru には入れていません。

また `AUX` は品詞マッピングに無いので、`был` / `будет` は数えられていません。

**決めること:** Media of Langue におけるロシア語コピュラの正規形（おそらく `быть`、
`есть` / `являться` は別項目）。`AUX` を `v` に写すかどうか。

### A6. 否定辞の範囲を決める

現状は `не` のみ、後続1トークンを除外します。

```python
TokenIgnoreRule(words=("не",), offset=1, case_insensitive=True)
```

**動くケース:**
```
Я не читал книгу.   -> читал を除外   （正しい）
Не забудьте книгу.  -> забудьте を除外（正しい。文頭大文字は修正済み）
```

**動かないケース（確認済み）:**
```
Речь шла не об отказе от роскоши.
  -> 「об」（前置詞）を除外してしまい、否定されている「отказе」が残る
```

オフセット +1 が「隣接」を仮定しているためです。ロシア語は否定辞と内容語の間に前置詞が
入ることが普通にあります。修正するなら `TokenIgnoreRule` を拡張して
「品詞コードが空のトークンを飛ばして、次の**内容語**を除外する」形にするのが素直です。

**未対応の否定表現:**

| 表現 | 状況 |
|---|---|
| `нет`（〜が無い） | 未対応。英語側は `don't have` で内容語を落とすのに露側は残る |
| `нельзя`（〜してはいけない） | 未対応。英語側は `can't` で落ちる |
| `ни ... ни` | 未対応 |
| `никто / ничего / никогда` | 二重否定。`не` が拾うので偶然動く場合がある |
| `не` 接頭辞（`небольшой`, `невозможно`） | トークンルールでは原理的に無理。`normalize_data` の仕事 |
| **`не только`（〜だけでなく）** | **誤発火**。否定ではないのにルールが発動する |

最後の `не только` は誤りが確実なので、優先度が高いです。

**完了の目安:** ロシア語の否定方針が文書化され、`en_ru` の `trg_ignore_rules` に反映されて
いること。あるいは「初版は `не` のみを対象とする」と明示的に宣言すること。
**同じファイルに `en_it` と `en_ko` のコピペ由来バグが保存されています。あれを真似しないでください。**

### A7. コーパスの洗浄基準を決める

ParaCrawl は web クロールなので、そのままでは使えません。実際に smoke データに入っているもの:

- アダルトサイトのタグ列（`shemalez`, `xhamster` が wordlist の1番と2番に入っています）

**決めること:** どの水準で切るか。Bicleaner のしきい値、タグ列の除去、言語判定の導入。

## 4. 既知の落とし穴

### 解析に失敗した語が黙って通ります

`lemmatize_word` は MorphVocab が解析できないと**入力をそのまま返します**。

```
xhamster → xhamster
фывапролд → фывапролд
```

失敗のシグナルが無いので、コーパスのゴミが正当なレンマの顔をして wordlist に入ります。
`tests/test_ru_language.py` にこの挙動を固定するテストがあります。

### pymorphy2 は保守終了しています

Natasha はレンマ化を pymorphy2 経由で行いますが、pymorphy2 は保守されておらず、
`pkg_resources` の廃止警告を出します。直接使うと Python 3.12 で壊れるという報告もあり、

当てはまりません。品質がおかしいと感じたら、まずここを疑ってください。

### 多語表現は語ごとにレンマ化されます

複数語が1つの語彙単位として貼り合わされた場合、単一の品詞タグで語ごとにレンマ化するので、
ロシア語の一致（格・性・数）が壊れて非文法的な擬似語彙ができます。
